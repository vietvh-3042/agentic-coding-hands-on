## Overview

**Priority:** P1 — blocking gate for every other phase
**Status:** done
**Effort:** 1h

The repository does not build today. Install the missing runtime dependencies, remove the broken
`next-intl` plugin wiring, install the E2E toolchain, and prove `pnpm validate` exits 0. Nothing
in this phase is feature work — it is the precondition that makes an `e2e-red-first` RED
_meaningful_ rather than an infrastructure accident.

## Key Insights

- `i18next` and `react-i18next` are imported by ~30 components (`lib/i18n/i18n.ts` and every
  `useTranslation` caller) but appear in neither `package.json` nor `pnpm-lock.yaml`.
  `pnpm typecheck` exits **2** with ~30 × TS2307; `pnpm lint` exits **1**.
- `react-i18next@17`'s only breaking change is `<Trans>` auto-key serialization. This codebase
  uses **zero** `<Trans>` — only `useTranslation`, `I18nextProvider`, `initReactI18next`
  (verified in `lib/i18n/i18n.ts` and the component tree). The major bump is a safe add.
- **New finding, not in the scout report:** `next.config.ts` calls
  `createNextIntlPlugin("./i18n/request.ts")` and `i18n/` **does not exist**. The scout's claim
  that "zero files import next-intl" is wrong — the build config does. This is a second
  build-blocker and it sits directly under Playwright's `webServer: pnpm build && pnpm start`.
- Removing the plugin is _consistent with_, not a deviation from, the "do not migrate to
  next-intl" constraint: the codebase standardized on react-i18next, so the plugin is dead
  wiring pointing at a missing file.
- `tsconfig.json` `include` is `**/*.ts` with `exclude: ["node_modules"]` — a future `e2e/` dir
  is type-checked automatically. Playwright types must therefore resolve or `pnpm typecheck`
  breaks. Installing `@playwright/test` here (not in Phase 02) keeps that invariant.

## Requirements

**Non-functional**

  fail).
- No secrets, no `.env*` files touched in this phase.

## Implementation Steps

1. `pnpm add i18next@26.4.2 react-i18next@17.0.13`
2. `pnpm remove next-intl` — nothing imports it once step 3 lands.
3. Edit `next.config.ts`: delete the `createNextIntlPlugin` import and the `withNextIntl` const;
   change the default export to `nextConfig`. Leave `images.remotePatterns` untouched.
4. `pnpm add -D @playwright/test@1.63.0 eslint-plugin-playwright@2.11.0`
5. `pnpm exec playwright install --with-deps chromium` — this shell runs as root on WSL2, so
   `--with-deps` (apt) will succeed without `sudo`. Chromium only; webkit/firefox are dead
   weight for a single-project config.
6. Add scripts to `package.json`:
   `"test:e2e": "playwright test"`, `"test:e2e:ui": "playwright test --ui"`.
   Do **not** add `test:e2e` to `validate`.
7. Run `pnpm typecheck`, then `pnpm lint`, then `pnpm build`. Record exit codes.
8. Re-run `pnpm format:check`; run `pnpm format` if the dependency edits perturbed formatting.
